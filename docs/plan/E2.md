# SimpasID · Э2 — план реализации для Claude Code

> **Для агента-исполнителя:** ОБЯЗАТЕЛЬНАЯ ПОД-СКИЛ: `superpowers:subagent-driven-development`
> (рекомендуется) либо `superpowers:executing-plans`. Шаги размечены чекбоксами `- [ ]`.
> Перед каждой задачей — `security-guidance`, после — `superpowers:requesting-code-review`.
> Перед закрытием этапа — `superpowers:verification-before-completion`.

**Цель:** поднять SimpasID как работающий OIDC-issuer с публичным API v1, порталом аккаунта и
ресурсом разработчика — так, чтобы любой сервис СИМПАС мог переехать на него, прочитав только
документацию, и чтобы при этом ни один живой пользователь ПРАКТИКИ или ЗАПИСОК не был
разлогинен.

**Архитектура:** свой тонкий сервис на Fastify + Postgres со зрелой библиотекой протокола
внутри (`oidc-provider` panva) — протокол не пишется руками, пишутся только адаптер хранения,
`findAccount` и экраны. Поверх — публичный REST API v1, описанный OpenAPI 3.1; портал аккаунта
и все продукты работают **этим же** API, внутреннего пути не существует. Отдельный домен,
отдельная база, отдельный проект Compose — падение SimpasID не трогает соседей.

**Стек:** Node.js + TypeScript, Fastify, `oidc-provider`, `pg` (без ORM — как в сервере
ЗАПИСОК), Postgres, Vitest, OpenAPI 3.1 + Spectral, Docker Compose.

## Глобальные ограничения

Действуют в **каждой** задаче плана. Нарушение любого — брак, а не замечание.

1. **И-1.** SimpasID не хранит, не принимает и не передаёт ключевой материал ЗАПИСОК: ни пароль
   хранилища, ни хеш, ни обёрнутый мастер-ключ, ни соль, ни подсказку.
2. **И-2.** Ни одна схема не содержит колонок с именами `password`, `password_hash`,
   `passphrase`, `vault_key`, `master_key`, `wrapped_key`, `key_material`, `recovery_key`,
   `kek`, `secret_key`, `phone`, `otp`, `sms_code` и производных.
3. **И-3.** Действующая сессия SimpasID не открывает ни одной зашифрованной заметки.
4. **И-4.** ЗАПИСКИ работают полностью офлайн; SimpasID не имеет права это тронуть.
5. **И-5.** Внешний провайдер не может быть единственным способом входа: у каждой учётной
   записи всегда есть подтверждённая почта.
6. **Принцип аддитивности.** Ни одна операция в репозиториях продуктов не трогает `User`,
   `Account`, `Session` (ПРАКТИКА) и `users`, `sessions` (ЗАПИСКИ) иначе как **добавлением**
   строк. Никаких `UPDATE` по идентификаторам, никаких удалений.
7. **Ни одной собственной криптографии.** Только библиотека и `node:crypto`. Ни одного
   самописного сравнения токенов, подписи, генератора состояния.
8. **В журналы не пишутся** почта, `sub`, токены и пути. Только `ip_hash` и `ua_hash`.
9. **Юридические механики** (задание 08 §2.1): договоры — акцепт действием без обязательного
   чекбокса; Политика — без акцепта; рекламное согласие — отдельное, по каналам, выключено;
   заверение — единственный обязательный чекбокс, и он не в этом этапе.
10. **Язык интерфейса.** Слов «OAuth», «токен», «OIDC», «провайдер идентичности», «SimpasID»,
    «сессия» в техническом значении на экранах нет. Человек видит «Аккаунт СИМПАС», «способы
    входа», «устройства и сеансы», «ключ доступа».
11. **`context7` обязателен** перед любым утверждением про `oidc-provider`, Fastify, `pg`,
    `next-auth`. Один вопрос — один вызов. Ответ фиксируется в отчёте задачи.
11а. **Мобильные приложения не уходят в браузер и не открывают наш веб.** Вход в них — только
    через первичный токен-API (`docs/spec/12_NATIVE_AUTH.md`). Форма логина провайдера внутри
    нашего приложения и встроенный webview для входа запрещены безусловно. Веб-продукты
    продолжают ходить через OIDC с редиректом — требование касается мобильных клиентов.
12. **Правило достоверности.** Путь к файлу в чужом репозитории проверяется чтением, а не
    доверием этому плану. Где план говорит «проверить фактический путь» — это обязательство.

## Где это живёт: репозитории, домен, контур публикации

| Что | Значение |
|---|---|
| Репозиторий сервиса | `github.com/compas-psy/auth` — **агент работает только здесь** |
| Домен сервиса | `auth.cmpas.ru` |
| `issuer` | `https://auth.cmpas.ru` |
| Базовый адрес API | `https://auth.cmpas.ru/v1` |
| Ресурс разработчика | `https://auth.cmpas.ru/dev` |
| Портал аккаунта | `https://auth.cmpas.ru/account` |
| Адрес обратного вызова ПРАКТИКИ | `https://cmpas.ru/api/auth/callback/simpasid` |
| Сервер публикации | тот же боевой сервер, к которому подключён репозиторий `compas-psy/cmpas.ru` |

**Это меняет Задачу 16 и вводит три требования, каждое обязательное.**

### Требование Р-1. Тот же сервер — но не тот же контур

`02_SIMPASID.md` §3.4 п. 4 требует изоляции: отдельный проект Compose, отдельная база,
отдельный том, лимиты памяти. ADR-0003 ЗАПИСОК называет худшим исходом «уронить работающий
продукт соседа». Публикация на общий сервер это требование **не отменяет**: общим остаётся
только железо и реверс-прокси. Свой `COMPOSE_PROJECT_NAME`, своя база, свой том, свои лимиты.
Контейнер SimpasID не имеет доступа к базе ПРАКТИКИ ни в какой форме.

### Требование Р-2. Cookie не поднимается на общий домен

`auth.cmpas.ru` — поддомен `cmpas.ru`, и это опасная деталь, которой не было, пока домен был
отдельным. Cookie сессии SSO ставится **только на хост** `auth.cmpas.ru`: атрибут `Domain`
не задаётся вовсе. Задать `Domain=.cmpas.ru` означало бы, что cookie сервиса идентичности
уезжает в ПРАКТИКУ и в любой другой поддомен при каждом запросе — то есть сессия, дающая
право сменить способ входа, оказывается там, где ей делать нечего.

Обязательно: `HttpOnly`, `Secure`, `SameSite=Lax`, префикс `__Host-` в имени cookie (он
запрещён к использованию с атрибутом `Domain` на уровне браузера и потому сам страхует от
ошибки). Проверяется тестом в Задаче 16.

### Требование Р-3. Учредитель ничего не прописывает руками

Всё, что можно сделать из репозитория, делает агент: сборка образа, публикация образа,
конфигурация прокси, миграции, генерация и ротация ключей подписи при первом запуске,
переменные окружения без секретов, health-check, лимиты, бэкап базы.

Физически невозможны из репозитория и остаются человеку ровно два действия, оба разовые:

1. **A-запись `auth.cmpas.ru`** у регистратора (П-3);
2. **один набор секретов деплоя** в `Settings → Secrets` репозитория `auth`, если выбран
   вариант Б в Задаче 16. При варианте А (рекомендуемом) не нужен и он.

Всё остальное — включая правку в репозитории `cmpas.ru`, если она понадобится, — агент
готовит **готовым к применению**, а не описывает словами. Ничего не «прописывается вручную»:
человек либо жмёт кнопку слияния, либо выполняет одну строку, скопированную из отчёта.

```ts
import { describe, it, expect } from "vitest";
import { readdirSync, readFileSync } from "node:fs";
import { join } from "node:path";

const MIGRATIONS = join(__dirname, "../src/db/migrations");

const FORBIDDEN = [
  "password", "password_hash", "passphrase", "vault_key", "master_key",
  "wrapped_key", "key_material", "recovery_key", "kek", "secret_key",
  "phone", "otp", "sms_code",

    .filter((f) => f.endsWith(".sql"))
    .map((f) => readFileSync(join(MIGRATIONS, f), "utf8"))
    .join("\n")
```

```sql
-- 0001_identity.sql
CREATE TABLE accounts (
  id                    uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  status                text NOT NULL DEFAULT 'active'
                        CHECK (status IN ('active','suspended','deletion_requested','deleted')),
  display_name          text,
  created_at            timestamptz NOT NULL DEFAULT now(),
  updated_at            timestamptz NOT NULL DEFAULT now(),
  deletion_requested_at timestamptz,
  deleted_at            timestamptz
);

CREATE TABLE account_emails (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id  uuid NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  email       text NOT NULL,
  verified_at timestamptz,
  is_primary  boolean NOT NULL DEFAULT false,
  added_at    timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX account_emails_lower_key ON account_emails (lower(email));
CREATE UNIQUE INDEX account_emails_one_primary
  ON account_emails (account_id) WHERE is_primary;
```

```ts
// server/src/oidc/adapter.ts
import { getPool } from "../db/pool.js";

export class PostgresAdapter {
  constructor(private type: string) {}

  async upsert(id: string, payload: Record<string, unknown>, expiresIn: number) {
    await getPool().query(
      `INSERT INTO oidc_payloads (id, type, payload, grant_id, user_code, uid, expires_at)
       VALUES ($1,$2,$3,$4,$5,$6, now() + ($7 || ' seconds')::interval)
       ON CONFLICT (type, id) DO UPDATE SET payload = EXCLUDED.payload,
         expires_at = EXCLUDED.expires_at`,
      [id, this.type, payload, payload.grantId ?? null,
       payload.userCode ?? null, payload.uid ?? null, String(expiresIn)],
    );
  }

  private async one(where: string, value: string) {
    const { rows } = await getPool().query(
      `SELECT payload, consumed_at FROM oidc_payloads
       WHERE type = $1 AND ${where} = $2
         AND (expires_at IS NULL OR expires_at > now())`,
      [this.type, value],
    );
    if (!rows[0]) return undefined;
    const p = rows[0].payload as Record<string, unknown>;
    if (rows[0].consumed_at) p.consumed = Math.floor(rows[0].consumed_at.getTime() / 1000);
    return p;
  }

  find(id: string) { return this.one("id", id); }
  findByUserCode(userCode: string) { return this.one("user_code", userCode); }
  findByUid(uid: string) { return this.one("uid", uid); }

  async consume(id: string) {
    await getPool().query(
      "UPDATE oidc_payloads SET consumed_at = now() WHERE type = $1 AND id = $2",
      [this.type, id]);
  }

  async destroy(id: string) {
    await getPool().query("DELETE FROM oidc_payloads WHERE type = $1 AND id = $2",
      [this.type, id]);
  }

  async revokeByGrantId(grantId: string) {
    await getPool().query("DELETE FROM oidc_payloads WHERE grant_id = $1", [grantId]);
  }
}
```

```sql
CREATE TABLE magic_link_tokens (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email      text NOT NULL,
  token_hash text NOT NULL UNIQUE,
  device_key text NOT NULL,
```

```ts
// server/src/services/magicLink.ts
import { randomBytes } from "node:crypto";
import { getPool } from "../db/pool.js";
import { sha256 } from "../lib/hash.js";
import { createAccountWithEmail, findAccountByEmail } from "./accounts.js";

const TTL_MINUTES = 15;
const THROTTLE_SECONDS = 60;

export async function issueMagicLink(i: { email: string; deviceKey: string; platform: string }) {
  const { rows } = await getPool().query(
    `SELECT 1 FROM magic_link_tokens
     WHERE lower(email) = lower($1) AND created_at > now() - interval '${THROTTLE_SECONDS} seconds'
     LIMIT 1`, [i.email]);
  if (rows.length) return { throttled: true as const };

  const token = randomBytes(32).toString("base64url");
  await getPool().query(
    `INSERT INTO magic_link_tokens (email, token_hash, device_key, platform, expires_at)
     VALUES ($1,$2,$3,$4, now() + interval '${TTL_MINUTES} minutes')`,
    [i.email, sha256(token), i.deviceKey, i.platform]);
  return { token };
}

export async function redeemMagicLink(token: string) {
  const pool = getPool();
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const { rows } = await client.query(
      `SELECT id, email FROM magic_link_tokens
       WHERE token_hash = $1 AND used_at IS NULL AND expires_at > now()
       FOR UPDATE`, [sha256(token)]);
    if (!rows[0]) { await client.query("ROLLBACK"); return null; }
    await client.query("UPDATE magic_link_tokens SET used_at = now() WHERE id = $1",
      [rows[0].id]);
    await client.query("COMMIT");
    const existing = await findAccountByEmail(rows[0].email);
    return existing ?? (await createAccountWithEmail(rows[0].email));
  } catch (e) {
    await client.query("ROLLBACK"); throw e;
  } finally { client.release(); }
}
```

## Стартовый комплект нового репозитория

Реализация идёт в репозитории `github.com/compas-psy/auth` отдельным агентом. У этого агента
**не будет** доступа к проекту КОМПАС, поэтому ссылки вида «`02_SIMPASID.md` §4.2» ему ничего
не скажут. До первой задачи в репозиторий кладётся комплект, после чего план становится
самодостаточным.

Соседний репозиторий `github.com/compas-psy/cmpas.ru` нужен агенту **на чтение** (Задача 16,
шаг 0) и, возможно, для одного PR. Права на запись в него не требуются: если их нет, агент
готовит патч, а не просит учредителя что-то настроить.

| Куда | Что | Зачем именно это |
|---|---|---|
| `/CLAUDE.md` | правила репозитория (готовый файл — соседний документ `11_SIMPASID_REPO_CLAUDE.md`) | агент читает его первым; в нём инварианты, запреты и порядок скилов |
| `/docs/spec/02_SIMPASID.md` | копия ТЗ архитектуры | источник И-1…И-5, §5 миграции, §8 угроз, §9 тестов |
| `/docs/spec/05_CONSENT_PDN.md` | копия ТЗ юрконтура | журнал согласий §2.2, права субъекта, §6.1 замена плоской таблицы журналом |
| `/docs/spec/08_AUTH_DESIGN_BRIEF.md` и `09_ACCOUNT_DESIGN_ADDENDUM.md` | задания на дизайн | дословные тексты экранов и юридические механики |
| `/docs/spec/12_NATIVE_AUTH.md` | нативный вход | отменяет Custom Tab и мобильный веб; источник задач Н1–Н4 |
| `/docs/spec/CMPAS_LEGAL_IMPLEMENTATION.md` | правила реализации юрпакета | §3 механики, §9 каналы, §21 запреты |
| `/design/` | распакованный `handoff/` из пакета макетов | `.dc.html` артборды, `_ds/tokens/*.css`, `assets/brand/`, знаки провайдеров |
| `/docs/plan/E2.md` | этот план | исполняется задача за задачей |

**Три вещи из комплекта, которые агент обязан прочитать до Задачи 1:** `CLAUDE.md`,
`design/ЧИТАТЬ_ПЕРВЫМ.md` (11 зафиксированных юридических пунктов), `docs/spec/02_SIMPASID.md`
§1.4 (инварианты).

**Чего в новый репозиторий класть не надо:** юридический пакет `.docx` с реквизитами ИП —

особенно касается ответов `context7`: они меняют содержание Задач 5, 6 и 15.
