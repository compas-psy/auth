# Журнал изменений API аккаунта СИМПАС

Каждая запись говорит, ломает ли изменение существующих потребителей, и до какого числа
работает прежнее поведение. Процедура одна: уведомление — срок миграции — отключение.

Формат заголовка: `## <версия> — <дата> — breaking|non-breaking`.

## 1.3.0 — 2026-09-11 — non-breaking

`GET /v1/auth/methods` на мобильных платформах отдаёт `provider_app_ids` — идентификаторы
НАШИХ приложений у провайдеров, по одному на провайдера из `providers`.

Зачем. Этим значением приложение инициализирует нативный SDK. Код, выданный провайдером,
принадлежит запросившему приложению, а обмен идёт нашими ключами: SDK, заведённый на
идентификатор приложения ПРОДУКТА, получит код, который мы обменять не сможем, и человек
увидит «вход не работает» без причины. Агент ПРАКТИКИ едва не сделал ровно это.

Берётся отсюда, а не вписывается в сборку: копия в четырёх продуктах разойдётся с
оригиналом, и никто не заметит, пока вход не отвалится.

Секретом не является: `client_id` едет в строке запроса каждого обращения к провайдеру.
Ключа приложения здесь нет и быть не может — закреплено проверкой.

В браузере поля нет: уход к провайдеру там делаем мы сами.

Запрос авторизации принимает необязательный параметр `provider` — подсказку, какого
провайдера человек выбрал в продукте. Подсказка ВЫБИРАЕТ, а не пропускает: наш экран
показывается всегда, названный провайдер встаёт первым и помечается, остальные способы
входа остаются на месте. Уход прямо к провайдеру пропустил бы юридическую строку, а
Пользовательское соглашение принимается действием на нашем экране и больше нигде.

Неизвестное или неподключённое значение не выделяет никого и входу не мешает: опечатка в
чужой ссылке не должна оборачиваться отказом.

Ломать нечего: поле и параметр необязательные.

## 1.2.0 — 2026-09-11 — non-breaking

`POST /v1/auth/provider/{provider}/native` принимает четыре новых необязательных поля:
`code_verifier`, `provider_device_id`, `state`, `redirect_uri`.

Зачем. В браузерном входе авторизацию начинаем мы и потому знаем и строку состояния, и
проверочный код PKCE. В нативном её начинает приложение — эти значения существуют только
у него. VK ID без всех трёх обмен не проводит; Яндексу хватает кода.

Подключены нативные адаптеры Яндекс ID и VK ID. `GET /v1/auth/methods?platform=android`
теперь называет провайдеров, код которых сервер готов обменять на личность. Есть ли у
приложения нативный SDK этого провайдера — знает только само приложение: оно рисует
пересечение того, что умеет сервер, и того, что умеет оно.

Ломать нечего: поля необязательные, прежний вызов с одним кодом работает как работал.

## 1.1.0 — 2026-09-11 — non-breaking

Добавлен `GET /v1/legal/documents` — действующие редакции документов Экосистемы: код,
название, номер редакции, неизменяемый адрес текста, способ принятия и — у Особых
условий — сервис.

Зачем. Продукт обязан предъявить человеку документ, который тот принимает, с номером
редакции и ссылкой на неё (`14_LEGAL_PRODUCTS_UNIFIED.md` §4). Взять номер было
неоткуда: `GET /v1/account/consents` отдаёт только УЖЕ принятые документы. Продукту
оставалось вписать номер в приложение руками — то есть однажды показать человеку не ту
редакцию, которую он принимает.

Входа ручка не требует: это публичные документы, и их читают до того, как человек завёл
учётную запись.

Документа без опубликованной редакции в ответе нет. Для сервиса это ответ «подключать
нечего»: подключение сервиса без Особых условий означает, что человек согласился с тем,
чего не существует.

Ломать нечего: ручка новая, прежние не изменились.

## 1.0.0 — 2026-09-06 — non-breaking

Первая опубликованная редакция контракта.

Шесть групп ресурсов: профиль и почты, способы входа, устройства и сеансы, согласия и
коммуникации, журнал событий, первичный вход для наших мобильных приложений.

Ломать нечего: прежних потребителей нет.
