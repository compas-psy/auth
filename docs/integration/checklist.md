# Чек-лист переезда на единый вход СИМПАС

Семь пунктов. Каждый проверяемый: если пункт нельзя предъявить, он не выполнен.

| # | Что сделать | Чем доказывается |
|---|---|---|
| 1 | Зарегистрировать клиента и получить ключ | ключ показан один раз при выдаче; повтор — только перевыпуск |
| 2 | Добавить провайдера **рядом** с существующими | в конфигурации остались все прежние способы входа, порядок на экране не менялся |
| 3 | Включить связывание по почте **только** для нашего issuer | флаг стоит у одного провайдера; у остальных его нет |
| 4 | Проверить `email_verified` в `id_token` | вход с неподтверждённой почтой отклоняется продуктом |
| 5 | Записать связывание в свой журнал | строка добавлена, ни одна существующая не изменена |
| 6 | Прогнать замер «число сессий до и после совпадает» | два SQL-запроса до и после дают одинаковые числа и одинаковую контрольную сумму |
| 7 | Наблюдать две недели | в журнале нет всплеска неудачных входов; жалоб на разлогинивание нет |

## Что обязан делать продукт

**Проверять `email_verified`.** Единый вход не выдаёт неподтверждённую почту, но продукт
не должен полагаться на чужую дисциплину.

**Проверять `nonce`.** Он обязателен и приходит в `id_token`. SDK делает это за вас, если
передать ожидаемое значение в `verifyIdToken`.

**Не обращаться к единому входу на каждый запрос.** Токен проверяется один раз, при входе;
дальше живёт своя сессия продукта. Это и есть причина, по которой недоступность единого входа
никого не разлогинивает.

**Показывать человеческий текст при недоступности.** «Вход временно недоступен. Мы уже чиним.
Попробуйте через несколько минут.» Никаких `ECONNREFUSED` на экране.

## Что продукт не получит никогда

Ролей, тарифов, прав, признака «психолог», списка продуктов, аватара и ФИО из внешнего сервиса.
В `id_token` есть `sub`, `email`, `email_verified` и — если человек ввёл его сам — `name`.
Права продукт узнаёт из своей базы по `sub`.

Телефона и пароля тоже не будет: их нет в схеме, и тест не даст им появиться.

## Порядок отката

1. Убрать провайдера из конфигурации. Строки `Account`/`simpas_links` остаются — они никому
   не мешают и понадобятся при повторной попытке.
2. Ничего не удалять в своей базе.
3. Сообщить, что именно пошло не так: это меняет спецификацию, а не только вашу настройку.
