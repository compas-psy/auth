# Аккаунт СИМПАС внутри продукта · общая инструкция

11.09.2026 · агентам **ПРАКТИКИ**, **ШАГОВ**, **МОМЕНТОВ** (и любого следующего продукта СИМПАСА)
Макеты: `дизайн/СИМПАС Аккаунт в продукте.dc.html`
Источники: `compas-psy/auth` — `docs/spec/09_ACCOUNT_DESIGN_ADDENDUM.md`, `docs/integration/checklist.md`, `portal/src/`

---

## 0. Зачем этот документ

Вход во все продукты идёт через `auth.cmpas.ru`. Если каждое приложение нарисует свой экран аккаунта, через месяц они разойдутся: где-то «Войти», где-то «Авторизоваться», где-то чекбокс согласия, которого не должно быть нигде.

Поэтому модуль «Аккаунт» — **один на все продукты**. Разметка, порядок блоков, отступы, радиусы и тексты кнопок общие. Меняются только две вещи:

1. **значения токенов** — модуль рисуется цветом и шрифтом хозяина;
2. **одно предложение заголовка** в состоянии «не вошли» — оно называет пользу в этом конкретном продукте.

Всё остальное совпадает буквально.

---

## 1. Кнопка называется «Войти»

Одно слово. Во всех местах, где встречается: раздел аккаунта, плашка истёкшего входа, любое приглашение подключить то, что требует аккаунта.

**Запрещено:** «Войти через СИМПАС», «Войти в СИМПАС ID», «Продолжить с SimpasID», «Войти с аккаунтом СИМПАС», «Авторизоваться».

Человек входит в продукт, которым пользуется. Имя провайдера в подписи кнопки превращает свой вход в сторонний — и заодно заставляет объяснять, что такое СИМПАС, до того как человек вообще решил войти.

Куда откроется вход — говорится **строкой рядом с кнопкой**:

> Вход откроется на `auth.cmpas.ru` — общей странице входа

## 2. Состояние «не вошли»

Карточка на подложке раздела, под ней юридическая строка вне карточки.

```
┌──────────────────────────────────────────────┐
│  ◉ СИМПАС                                    │
│                                              │
│  {Заголовок — польза в этом продукте}        │
│  {Что работает без аккаунта, если работает}  │
│                                              │
│  [ Войти ]   Вход откроется на auth.cmpas.ru │
└──────────────────────────────────────────────┘
  Продолжая, вы принимаете Пользовательское
  соглашение. Как мы обращаемся с данными —
  в Политике обработки персональных данных.
```

### Заголовки по продуктам

| Продукт | Заголовок | Вторая строка |
|---|---|---|
| **ПРАКТИКА** | Войдите, чтобы открыть свою практику | Расписание, карточки клиентов и заметки после сессий живут в аккаунте |
| **ШАГИ** | Аккаунт нужен, чтобы задачи были на всех устройствах | Списки на этом устройстве работают и без него |
| **МОМЕНТЫ** | Аккаунт нужен, чтобы практики продолжались с того же места | Слушать можно и без него |
| ЗАПИСКИ | Аккаунт нужен только для Облака Записок | Заметки, редактор, поиск, история, импорт и экспорт работают без него |

Правила для заголовка:

- называет **пользу**, а не сервис;
- отрицание заголовком быть не может: «аккаунт не нужен» не объясняет, зачем он существует;
- вторая строка пишется **только если это правда**. В ПРАКТИКЕ без аккаунта работать нечему — там второй строки про офлайн нет, а есть перечисление того, ради чего входят.

### Юридическая конструкция — одинакова везде

1. **Обязательного чекбокса нет.** Акцепт — действием, содержательной кнопкой.
2. Юридическая строка стоит **под всем блоком**, а не под одной кнопкой.
3. Политика упоминается **без глагола принятия**: это информационный документ, его не принимают.
4. Ссылки ведут на **конкретную редакцию**, а не на текущую.

Это не стилистика, а требование юридического пакета. Нарушение любого из четырёх пунктов блокирует приёмку.

## 3. Состояние «вошли»

Четыре блока в фиксированном порядке. Порядок не переставляется.

### 3.1. Кто вы

- знак СИМПАС (38 px) + почта + подпись «Аккаунт СИМПАС · вход через {провайдер}»;
- справа кнопка **«Аккаунт СИМПАС»** с иконкой внешней ссылки → портал;
- под карточкой: «Имя, почты, способы входа, устройства и рассылки настраиваются на `auth.cmpas.ru`».

**Аватара нет.** Он не запрашивается, не хранится и не показывается — это правило сервиса идентичности, а не решение дизайна. Телефона и ФИО из провайдера тоже нет: их нет в схеме.

### 3.2. Что аккаунт даёт здесь

Одна–три строки про то, что в **этом** продукте работает благодаря аккаунту, со ссылкой в соответствующий раздел настроек. Например: «Облако Записок · подключено · Настроить». Если в продукте без аккаунта не работает ничего — блок не нужен.

### 3.3. Что вам присылать

Только те согласия, которые **продукт собирал сам**. Рассылки по каналам и сервисам, «отключить всю рекламу», список принятых документов — на портале, здесь их нет и дублировать нельзя.

Оба (или сколько их есть) тумблера **выключены по умолчанию** — единственное исходное состояние. Тумблер показывает то, что записано на сервере, а не то, что нажали: иначе неудачный запрос оставит человека в уверенности, что он отписался.

Под блоком — ссылка на текст согласия с указанием редакции.

### 3.4. Выход

Вторичная кнопка «Выйти» + подсказка, что останется на устройстве. Подтверждение диалогом.

Выход из продукта **не выходит из аккаунта** на `auth.cmpas.ru` и не трогает другие приложения. Если это неочевидно вашей аудитории — скажите это подсказкой до нажатия, а не в диалоге.

## 4. Четыре переходных состояния · обязательны все

### 4.1. Единый вход недоступен

```
Вход временно недоступен. Мы уже чиним.
Попробуйте через несколько минут.
```

Технической ошибки на экране быть не должно: ни кода, ни `ECONNREFUSED`, ни адреса сервера.

Третью строку про работу без сети добавляют **только ЗАПИСКИ** — у них это правда по построению. Остальным продуктам обещать этого нельзя.

### 4.2. Вход истёк

Плашка, а не экран и не модалка: человека не выкидывают из приложения. Текст говорит, что перестало работать, и даёт кнопку **«Войти»**.

Причина, по которой это именно плашка: продукт продлевает свою сессию своим refresh-токеном и к единому входу за этим не ходит. Недоступность единого входа никого не разлогинивает — она задевает только новый вход.

### 4.3. Ждём возврата из браузера

```
Заканчиваем вход в браузере
Если вкладка закрылась — вернитесь сюда и нажмите «Войти» ещё раз
```

Без этого состояния закрытая вкладка оставляет человека перед кнопкой, которая якобы не сработала. На Android — Custom Tab, на десктопе и в вебе — системный браузер. После возврата приложение оказывается там, откуда уходило.

### 4.4. Подтверждение выхода

Диалог с прямым вопросом и указанием, что останется. Одно из немногих мест, где диалог законен.

## 5. Контракт токенов

Модуль **не содержит ни одного собственного значения цвета**. Всё берётся у хозяина:

| Токен | Где применяется |
|---|---|
| `--bg` | подложка раздела |
| `--surface` | карточка личности, карточка приглашения, диалог |
| `--line`, `--line-soft` | рамки карточек, разделители блоков и строк |
| `--text`, `--text-secondary` | заголовки и подписи · пояснения, юридическая строка |
| `--accent`, `--on-accent` | заливка и подпись кнопки «Войти», включённый тумблер, ссылки |
| `--r-md`, `--r-card` | кнопки и поля (14 px) · карточки (20 px) |
| `--font-sans`, `--font-mono` | весь текст · адрес `auth.cmpas.ru`, даты |

**Исключение одно: знак СИМПАС.** Файл `simpas-logo-disc.svg` ставится как есть — не перекрашивается, не обрезается, не перерисовывается, в тёмных темах остаётся собой. Это знак владельца аккаунта, а не элемент интерфейса.

Проверить отдельно: контраст подписи на заливке кнопки. У золотого акцента подпись тёмная (`#143D2F`), белая на золоте даёт 2.45:1 и не проходит.

Модуль обязан выглядеть корректно минимум в двух темах вашего продукта. Если тема одна — всё равно не хардкодьте значения: тёмная появится.

## 6. Чего не делать никогда

1. **Не рисовать форму входа внутри приложения** — ни поля почты, ни кнопок провайдеров, ни ввода кода из письма. Всё это на `auth.cmpas.ru` и там уже реализовано.
2. **Не редактировать личные данные** — имя, почты, способы входа, устройства, рассылки по сервисам живут на портале.
3. **Не обращаться к единому входу на каждый запрос.** Токен проверяется один раз, при входе; дальше живёт своя сессия продукта.
4. **Не показывать технических слов**: «токен», «сессия», «OAuth», «SimpasID», «passkey» на экранах отсутствуют. Если нужно назвать passkey — он называется «ключ доступа».
5. **Не ставить предустановленных галок согласия.**
6. **Не показывать ролей, тарифов и признака «психолог» из внешнего сервиса** — их там нет. Права продукт узнаёт из своей базы.
7. **Не добавлять SMS и звонки** как канал: телефона в схеме нет и не будет.

## 8. Что известно не про всех

Состояние авторизации и коммуникаций в **МОМЕНТАХ** не проверено: рабочей копии репозитория у дизайна не было. Кадры для МОМЕНТОВ нарисованы по общей схеме и подлежат сверке агентом продукта. Если в МОМЕНТАХ уже есть свой вход — он не ломается, единый добавляется рядом; правило аддитивности действует во всех продуктах.
